# Rust Coding Agent：分阶段教程

遵循 KISS 原则，每个阶段都保留可运行的版本。当前版本在阶段 6 之后继续整理可用性：通过 DeepSeek 查看与修改项目、执行验证命令，支持流式输出、请求中断和检查点恢复。各阶段快照保留在 `examples/`，可独立运行。

## 构建路线

| 阶段 | 目标 |
| --- | --- |
| 1：最小模型调用（已保留） | 同步发送一个问题，打印模型回答 |
| 2：多轮对话（已保留） | 输入循环、消息历史、退出和清空会话 |
| 3：只读工具（已保留） | 列目录、读文件、搜索文本 |
| 4：Agent 循环（已保留） | 连续调用工具，回传结果，限制步数 |
| 5：修改与验证（已保留） | 修改代码、执行命令、根据检查结果修复 |
| 6：可用性整理（当前） | 会话恢复、输出限制和运行体验 |

## 阶段 1：运行

需要 Rust 工具链，并且有一个 DeepSeek API Key。本项目使用 Rust 2024 edition，当前验证环境为 Rust 1.98.0；依赖版本由 `Cargo.lock` 固定。

先设置密钥（在 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 申请）：

```zsh
export DEEPSEEK_API_KEY="sk-…"
```

然后直接运行：

```zsh
cargo run --example stage1 -- "用一个简短例子解释 Rust 的所有权"
```

程序只从环境变量读取密钥（`DEEPSEEK_API_KEY` 或 `RUST_AGENT_API_KEY`），不读写任何凭据文件，也不会打印或复制密钥到项目。

回答输出到 stdout，进度和错误输出到 stderr。每次运行都是独立请求。

```sh
cargo run -- --help
cargo fmt --check
cargo clippy -- -D warnings
```

## 阶段 1：理解实现

从 `examples/stage1.rs` 的 `run()` 按顺序阅读：

1. 读取命令行问题，拒绝空输入。
2. 调用 `load_api_key()` 读取环境变量中的 API Key，检查密钥是否存在且非空。
3. 创建 `reqwest::blocking::Client`，设置连接和请求超时。
4. 发送带 Bearer 认证的 JSON 请求，并携带客户端名称及 `x-session-id` 会话标识。
5. 检查 HTTP 状态，从 `choices[0].message.content` 取出回答并打印。

阶段 1 使用三个依赖：`reqwest` 负责同步 HTTP 和 TLS，`serde_json` 构造与读取 JSON，`anyhow` 给失败步骤补充可读的错误信息。应用代码没有异步运行时配置、流式输出或框架抽象。

请求固定使用：

```text
POST https://api.deepseek.com/chat/completions
model: deepseek-flash
```

`deepseek-flash` 由 DeepSeek-V4.1-Flash-1017 提供；旧名 `deepseek-chat`、`deepseek-reasoner` 已于 2026-07-24 下线。另有 `deepseek-v4-pro` 可通过 `RUST_AGENT_MODEL` 切换。接口信息见 [DeepSeek API 文档](https://api-docs.deepseek.com/)（核对日期：2026-10-26）。

## 阶段 1：验收与边界

- 正常：已设置有效 `DEEPSEEK_API_KEY`，直接提问，终端出现模型回答，退出码为 0。
- 输入错误：没有问题或 API Key 缺失时，程序在请求前报错，退出码为 1。
- 请求错误：显示网络错误或 HTTP 状态；不会自动重试。

真实模型回答需要有效的 API Key 与网络，编译成功不等于远程接口调用成功。阶段 1 没有多轮记忆、代码读取、文件修改或工具调用。


## 阶段 2：运行多轮对话

```sh
cargo run
```

沿用同一个 `DEEPSEEK_API_KEY`，不需要新增配置。阶段 2 使用 `rustyline` 管理输入编辑和终端重绘，处理中文退格及光标移动。每行输入作为一个问题；等待回答后再输入下一行。

可以按下面的顺序验证（模型的具体措辞可能不同）：

```text
你> 请记住，我正在学习的项目叫小螃蟹。只回答收到。
助手> 收到。
你> 我正在学习的项目叫什么？
助手> 小螃蟹。
你> /clear
会话已清空。
你> 我正在学习的项目叫什么？不知道就直说。
助手> 我不知道你正在学习的项目名称。
你> /exit
```

空行被忽略；`/exit` 或输入结束（空输入时按 Ctrl-D）退出；`/clear` 清空历史并保留系统提示词。命令必须独占一行。带问题参数时仍支持原来的单次问答：

```sh
cargo run -- "解释 Rust 的借用"
```

## 阶段 2：理解实现

阶段 2 的完整代码保留在 `examples/stage2.rs`，按职责拆成几个小函数：

1. `run()` 根据是否传入问题参数，选择多轮或单次模式，并创建 HTTP 客户端。
2. `initial_messages()` 创建含一条 `system` 消息的历史，定义中文 Rust 助手的角色和能力边界。
3. `chat()` 读取一行输入，处理本地命令，把用户消息加入 `Vec<Value>`。
4. `ask()` 将消息列表发给模型，返回回答文本；`chat()` 再把回答以 `assistant` 角色追加到历史。
5. `new_session()` 创建会话标识。同一段对话复用该标识，清空后重新生成。

第二轮请求的消息顺序为：

```text
system → user（第一问）→ assistant（第一答）→ user（第二问）
```

模型的对话记忆来自每次重新发送的消息历史。会话请求头用于服务端缓存优化，不能替代消息历史。

如果请求失败，撤回刚追加的用户消息，保留之前完整的问答并继续等待输入。不会自动重试。凭据读取或终端读取失败则退出程序并报告错误。

## 阶段 2：验收与边界

已使用 DeepSeek 完成真实三轮验证：先告知项目代号“蓝鲸742”，第二轮模型正确复述，清空后再问回答“不知道”。空行、清空、退出与 EOF 也已通过本地检查。

- 第二轮能回答第一轮提供的项目名称。
- `/clear` 后，后续请求不再携带之前的问答。
- 空行和本地命令不发起模型请求；`/exit` 和 EOF 均能正常退出。
- 阶段 1 示例和原来的单次问答入口仍能运行。

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo build --examples
```

历史只存于进程内存，退出后丢失；当前没有历史裁剪，长对话可能触及模型上下文或订阅限制，可用 `/clear` 开始新对话。每次只处理一行输入，仍使用同步、非流式请求。下一阶段增加只读代码工具。

输入编辑：使用左右方向键移动光标、Backspace 删除字符；Ctrl-C 取消尚未提交的输入并重新显示提示符。`rustyline` 负责字符宽度与换行重绘，避免直接依赖终端回显导致中文删除残留。该行为只针对等待输入时，模型请求中的中断不在本阶段处理。


## 阶段 3：只读代码工具

```sh
# 阶段 2 仍可独立运行（含中文输入修复）
cargo run --example stage2
# 当前阶段交互模式
cargo run
# 当前阶段单次任务
cargo run -- "请读取 Cargo.toml 和 src/main.rs，说明项目依赖和程序入口。"
cargo run -- "请列出当前目录，并搜索 src 中包含 load_api_key 的行。"
```

工作目录是启动程序时的当前目录。模型通过 `tools` 参数获得三个函数定义，选择调用并返回 JSON 参数；Rust 执行本地只读操作，将结果作为 `tool` 消息回传。终端显示工具名称，正文交给模型分析。

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `list_directory` | `path` | 最多 200 个直接子项与截断标识 |
| `read_file` | `path` | 最大 64 KiB 的 UTF-8 文件文本 |
| `search_text` | `path`、`query` | 字面匹配的文件、行号和文本 |

`src/main.rs` 管理对话和模型协议，`src/tools/` 管理工具。没有新增 Rust 依赖。

本阶段每轮最多两次模型请求：第一次允许模型选择一批工具（最多 8 个，顺序执行），第二次禁用工具，让模型根据结果总结。不需要工具时只有一次请求。目录未知时，可以先询问目录，再在下一轮要求读取具体文件；自动连续探索放在阶段 4。

对话历史包含 assistant 工具调用、每个带对应 `tool_call_id` 的结果和最终回答。工具执行错误会以 JSON 返回模型；模型请求失败则回滚整轮新增消息，保留此前完整历史。

所有工具路径先解析为真实路径，再检查是否位于工作目录内，拒绝 `..` 和指向目录外的符号链接。搜索不跟随遇到的符号链接，跳过隐藏项、`target`、`node_modules`；最多检查 2000 项、返回 50 条匹配，每条最多 300 字符，跳过不可读、过大或非文本文件。截断标识和跳过数量用于说明结果不一定完整。此路径检查不是用于防御其他进程同时替换文件的操作系统沙箱。

工具读取的内容会发送到 DeepSeek。请在准备让模型查看的项目目录中运行；当前只读工具不提供文件修改或命令执行。

验证命令：

```sh
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --examples
cargo build
python3 tests/terminal_input.py
```


### 工具代码的阅读顺序

```text
src/tools/
├── mod.rs             # Tool 接口、工具注册、统一定义与调用入口
├── common.rs          # 共享路径边界检查和限量文本读取
├── list_directory.rs  # 目录工具：描述、参数、执行逻辑
├── read_file.rs       # 文件工具：描述、参数、执行逻辑
└── search_text.rs     # 搜索工具：描述、参数、执行逻辑
```

先读 `mod.rs` 的 `Tool` trait：每个工具实现 `name`、`description`、`parameters`、`execute` 四个方法。再从最简单的 `read_file.rs` 开始看实现。

Agent 只调用 `tools::definitions()` 和 `tools::execute(root, name, args)`。两者使用同一个 `registry()`，让提供给模型的工具与实际可执行的工具保持一致。`&dyn Tool` 表示通过统一接口调用不同工具，无需 Agent 判断具体工具类型。

新增工具时，创建对应文件并实现 `Tool`，然后在 `mod.rs` 声明模块、加入注册列表并调整数组长度；Agent 无需修改。工具集合固定在编译期，不涉及动态插件加载。

响应诊断：总结请求会明确要求根据现有工具结果回答。解析保留结束原因，兼容字符串和文本块正文；截断、总结阶段再次调用工具、空正文会分别报错。只检测推理内容是否存在，不打印推理原文，也不会将其替代最终答案。没有自动追加请求。


## 阶段 4：有上限的 Agent 循环

阶段 3 的源码（含工具模块）完整保存在 `examples/stage3/`：

```sh
cargo run --example stage3
cargo run
cargo run -- "先查看项目目录，再找到程序入口，阅读相关文件后解释一次问答的执行流程。"
```

当前 Agent 能根据上一批工具结果决定下一步。例如：列目录 → 读取发现的文件 → 搜索相关函数 → 总结。工具保持只读，统一 `Tool` 接口不变。

`ask()` 连接真实模型请求；`run_steps()` 负责循环，两者通过一个请求函数参数连接，方便用本地模拟模型验证流程。每步：请求模型 → 有工具就执行并回传 → 没有工具就返回最终回答。

每轮最多 8 次模型请求：前 7 次允许调用工具，每批最多 8 个；第 8 次禁用工具并明确要求总结已有结果。达到上限时会显示提示，若模型仍要求工具则报错退出本轮，不再执行。上限是模型请求次数，不是工具总数，也不是墙钟时间；每次请求仍有 180 秒超时。

工具错误回传给模型，允许下一步换路径或调整参数；网络、响应解析错误会终止本轮，交互模式撤回本轮历史。没有自动网络重试，也不会无限循环。阶段 5 才加入修改与执行命令。

本地验收覆盖：连续工具调用、工具失败后读取正确文件、结果 ID 对应、预留最后总结步骤、模型不遵守上限时停止；此前响应解析、路径边界和中文输入测试继续保留。真实 DeepSeek 多步验收尚未完成，不能将模拟测试视为真实服务验证。


## 阶段 5：修改、验证与修复

```sh
cargo run --example stage4  # 保留的只读 Agent
cargo run                  # 当前阶段
```

示例任务：`读取 src/main.rs，将帮助信息里的“多轮对话”改为“交互对话”，修改后运行 cargo check。`

新增两个独立工具文件，沿用 `Tool` 接口和注册机制：

- `replace_text`：参数为 `path`、`old_text`、`new_text`。只修改已有 UTF-8 文件，旧内容必须非空且唯一。终端显示文件路径、起始行、删除段（-）与新增段（+），输入 `yes` 才写入。确认后重新检查文件内容，防止覆盖等待期间的改动。
- `run_command`：参数为 `command`。显示完整命令及工作目录，输入 `yes` 后通过 `/bin/sh -c` 执行，返回退出码、stdout、stderr 和超时标识。每个输出流保留前 32 KiB，其余丢弃但继续读取，避免管道堵塞。

拒绝、Ctrl-C、EOF 或非交互输入均不执行操作，错误回传模型。每次调用单独确认，没有自动批准模式。工具确认复用 `rustyline`，保持中文输入编辑体验。

命令在启动目录执行，但具有当前用户权限，工作目录并非沙箱；网络及目录外访问也可能发生。命令 stdin 关闭，不支持交互式程序。120 秒后结束命令进程组；普通后台子进程也会清理，主动脱离进程组的守护进程不在此保证内。当前命令执行面向 macOS/Linux。

模型可以在同一轮内完成：读取 → 提议替换 → 用户确认 → 执行检查 → 根据失败输出继续修改。仍受 8 次模型请求上限约束。请求失败时撤回对话历史，但已经批准的文件修改与命令副作用不会自动撤销。文本写入使用普通文件写入，不提供事务或崩溃恢复；当前不支持创建文件及任意补丁。

本地验证覆盖精确匹配、写入及过期内容拒绝、命令非零退出、输出捕获与超时；真实模型驱动的修改闭环尚待验证。新增 `libc` 仅用于 Unix 命令进程组的终止。


## 阶段 6：保存、恢复与可用性

```sh
cargo run --example stage5  # 阶段 5 快照
cargo run                  # 新会话
cargo run -- --resume      # 恢复当前项目已保存的会话
```

| 命令 | 行为 |
| --- | --- |
| `/help` | 显示命令清单 |
| `/save` | 将当前会话保存到 `.rust-agent/session.json`，覆盖上次保存 |
| `/load` | 用磁盘会话替换当前会话，失败则保留当前内容 |
| `/recover` | 恢复自动检查点 `.rust-agent/checkpoint.json`（含中断时的半成品历史，见文末长程任务） |
| `/continue` | 让模型核实磁盘和已有结果后继续未完成的目标 |
| `/status` | 显示模型、工作目录、会话、存档路径、消息数量、工具调用次数、上下文大小和步数限制 |
| `/clear` | 清空内存历史并生成新会话 ID，不删除已保存会话 |
| `/exit` / Ctrl-D | 退出；需要保留进度时先 `/save` |

保存是显式操作，不自动保存，也不自动覆盖尚未恢复的历史。新模块 `src/session.rs` 负责文件格式、校验与写入。保存会话 ID、工作目录、版本及消息（含工具结果），不保存认证配置。Unix 上文件权限为 0600，先写临时文件再重命名，避免常规写入失败破坏旧存档；目录已加入 `.gitignore`。会话可能包含已读取的项目内容，请按项目资料保管。

恢复校验版本、目录、角色及工具调用 ID 配对，并替换为当前版本的系统提示词。恢复不重放工具，也不执行过去的命令。只保留一个存档，不支持多进程同时保存；恢复只恢复对话，不恢复磁盘文件状态。

请求 JSON 最大 512 KiB，超出时本地拒绝发送并提示保存、清空或缩小任务。使用字节限制而非精确 token 计数，不会自动裁剪历史或拆散工具调用。响应最多读取 2 MiB，存档上限 4 MiB；既有文件读取、搜索结果、命令输出上限继续生效。

网络连接超时 15 秒、单次模型请求超时 180 秒；显示每步进度及成功读取响应的耗时。已有错误处理区分 HTTP 失败、输出截断、空回答和工具错误。仍不自动重试具有潜在副作用的整轮任务。

## 当前版本的模块结构

```text
src/
├── main.rs       # 参数解析、初始化和顶层错误处理
├── chat.rs       # 终端输入、会话命令和历史管理
├── agent.rs      # 系统提示词、多步循环和工具结果回传
├── model.rs      # HTTP 客户端、流式请求和响应解析
├── tui.rs        # 终端渲染：列宽、进度行、流式输出与中断处理
├── auth.rs       # API Key 环境变量读取
├── session.rs    # 会话文件保存、校验和恢复
└── tools/        # 统一 Tool 接口和各个工具实现
```

阅读顺序建议：`main.rs` → `chat.rs` → `agent.rs` → `model.rs` / `tui.rs` / `tools/`。单次任务由 main 直接调用 agent，交互任务由 chat 调用 agent；chat 使用 session 管理存档，也负责 `.rust-agent/history` 输入历史；tui 只处理显示与中断，不参与模型协议。模型响应测试放在 model，Agent 循环测试放在 agent，渲染测试放在 tui。

前文阶段说明描述的是当时的布局；当前版本已按职责拆分，各阶段 `examples/` 保持原样以供对照。拆分没有新增依赖或异步运行时；之后的提交在 `tui.rs` 加入流式渲染与请求中断，行为变化见下文两节。


## 接入其他 OpenAI 兼容接口（可选）

默认使用 DeepSeek 的 `deepseek-flash`。五个环境变量可以覆盖默认配置，用来接入其他兼容 `/chat/completions` 的服务（需要支持工具调用与 SSE 流式协议）：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | API Key | 无，缺失则报错退出 |
| `RUST_AGENT_API_KEY` | API Key，优先于 `DEEPSEEK_API_KEY` | 无 |
| `RUST_AGENT_ENDPOINT` | 完整请求地址 | `https://api.deepseek.com/chat/completions` |
| `RUST_AGENT_MODEL` | 模型名 | `deepseek-flash` |
| `RUST_AGENT_THINKING` | 思考模式，`enabled` 打开 | `disabled` |

DeepSeek 的 `thinking` 默认为开启，这里显式关闭：工具调用循环需要的是稳定、可预期的回答正文。需要长推理时再打开，代价是更多输出 token 与更长延迟。

> `thinking` 是 DeepSeek 的扩展字段，只在走默认 DeepSeek 端点时发送；切到其他兼容服务时不带该参数，避免请求被拒。

例如切换到本机的 MiMo Token Plan：

```sh
export RUST_AGENT_API_KEY="tp-…"
export RUST_AGENT_ENDPOINT="https://token-plan-cn.xiaomimimo.com/v1/chat/completions"
export RUST_AGENT_MODEL="mimo-v2.6-pro"
cargo run
```

切换后启动横幅和 `/status` 会显示实际模型，提供商标注随之变为「自定义端点」；工具、确认流程和系统提示词保持不变。

仓库根目录的 `run-mimo.sh` 把上面的流程封装成脚本：运行时从本机 mimocode 配置读取 key（也可先用 `RUST_AGENT_API_KEY` 覆盖），参数直接透传给 `cargo run`。在项目目录内使用：

```sh
./run-mimo.sh            # 交互模式
./run-mimo.sh "问题"     # 单次问答
./run-mimo.sh --resume   # 恢复会话
```


## 终端渲染与中断（当前版本）

交互运行时（stderr 是终端）回答按 SSE 分片实时显示，等待期间显示转圈进度和已用时间；stderr 不是终端时（测试、管道或重定向运行）自动退化为非流式请求，行为与拆分前一致。

工具活动可视化：每次调用显示工具名和参数（值按列宽截断），结果给出摘要（行数、匹配数、退出码或超时）和耗时，失败用 `✗` 标出；`run_command` 额外预览输出末尾最多 8 行（更长时带省略提示），编译错误一类的问题不必等模型转述。

所有行按显示列计算宽度：CJK 字符占两列，超宽内容截断或换行；状态信息走 stderr，回答正文走 stdout，重定向时互不污染；非 TTY 或设置 `NO_COLOR` 时不输出颜色。

Ctrl+C 在等待模型响应或执行命令时取消当前操作：已收到的流式内容保留，命令的整个进程组被终止；在输入提示符处按下则清空当前行，再按一次退出；连续三次信号可强制退出无响应的进程。

输入历史保存在 `.rust-agent/history`（0600 权限），方向键可跨会话召回，文件最多保留 500 条；`/status` 显示历史条数、工具调用次数和上下文大小。


## 文件写入与长程任务（当前版本）

```sh
cargo run -- --max-steps 64
cargo run -- --max-steps 64 "创建一个带单元测试的 Rust 示例，运行检查并修复失败。"
cargo run -- --max-steps 64 --resume
```

`--max-steps` 放在问题或 `--resume` 前面，默认 32，范围 2–256。最后一次模型请求只总结已完成工作、验证情况及待办。仍有限额，不能保证任意大任务一轮完成；输入 `/continue` 可继续未完成的目标。

新增 `write_file(path, content)` 工具：创建文件、自动创建父目录，也可完整覆盖已有文件。逐次展示完整前后内容并确认，最多 64 KiB。小范围修改继续使用 `replace_text`。写入先生成同目录临时文件，覆盖使用重命名；新建使用硬链接以拒绝覆盖并发出现的文件。覆盖保留原权限。该实现不防御恶意进程并发替换目录，不等同于文件系统沙箱。

每次任务自动写入 `.rust-agent/checkpoint.json`，在请求前、工具执行前和每个工具结果返回后更新，最终回答也写入。`/save` 仍保存独立的 `session.json`。两者互不覆盖：

- `--resume` 优先恢复 checkpoint；没有时恢复手动存档，只进入对话，不自动执行。
- `/recover` 恢复检查点，`/load` 恢复手动存档。
- `/continue` 让模型核实磁盘和已有结果后继续；每次写入和命令仍须确认。
- 错误不再回滚本轮历史，保留已执行操作。检查点写入失败时停止进一步执行。

执行前的检查点为每个工具预填“结果未知”，执行后逐项替换为真实结果。这覆盖了在命令或写入执行中进程被关闭的情况；恢复不会自动重放不确定操作，也不承诺恰好一次执行。恢复后应核实已有文件和仍可能运行的进程。

历史超过 300 KiB 时缩短较早的工具输出，保留最近 8 条消息、全部用户指令和工具调用配对；缩短处带提示，必要时重新读文件。这是有损输出裁剪，不是语义摘要。已有 512 KiB 请求上限继续生效；如果用户指令或工具参数本身过大，仍需缩小任务。保存恢复上限 4 MiB 不变。

长程能力是有界执行和可恢复的前台任务，并非后台调度服务。进程退出后不会自行运行，命令的权限确认不会因恢复被跳过。当前支持创建、覆盖、修改、验证及恢复，但真实模型端到端验收状态与此前说明相同。
